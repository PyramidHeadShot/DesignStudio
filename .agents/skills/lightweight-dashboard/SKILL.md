# Лёгкий веб-дашборд — проверенный рецепт

Происхождение опыта: промышленная система видеонаблюдения (Python 3.14/Windows,
CPU-bound инференс, 1–4 камеры), дашборд оператора на localhost. Версия 4.3,
2026-09. Каждая «подводная камня» ниже — реальная жалоба пользователя, не теория.

## 0. Спроси заказчика до старта (6 вопросов)

1. Доступ: только localhost или LAN? (localhost → без аутентификации; LAN → Basic Auth + предупреждение про открытый WiFi)
2. Что в галерее: какие типы событий и нужны ли метки типа на карточке?
3. Есть ли видео-архив (непрерывная запись)? Нужны ли клипы событий поверх галереи?
4. Как открывать видео: страница-плеер (рекомендуется) или прямая ссылка?
5. Часовой пояс сортировки/часов — часы по стене (00–23) или «последние 24 часа»?
6. Автообновление: да/нет и допустимая задержка (обычно 2–3 с — устраивает всех).

## 1. Стек — закрытое решение, не изобретать

- **Flask 3 + Jinja2 SSR** через `render_template_string` (шаблоны строками, без
  папки templates/blueprints/extensions) + **один `dashboard.js`** (fetch-поллинг).
- CSS — инлайн в HTML (один файл стилей `_CSS` строкой; `style-src 'unsafe-inline'`
  в CSP разрешён, скрипты — только свои).
- **НЕ использовать**: Node.js/сборку/SPA/React/Vue, HTMX, WebSocket/SSE,
  masonry-библиотеки, jQuery, CDN-ресурсы. Обоснование: приложение CPU-bound
  (инференс), дашборд не должен соревноваться за CPU; самописный `http.server`
  даёт больше кода (routing/ETag/Range) чем весь Flask; FastAPI — лишний event loop.
- Запуск: `werkzeug.serving.make_server(host, port, threaded=True)` в daemon-потоке
  (не `app.run`), остановка `server.shutdown()`. Привязка по умолчанию `127.0.0.1` —
  если заказчик просит `0.0.0.0`, но LAN не оговорён — подстраховка: слушать
  `127.0.0.1` + warning в лог.
- Минимальные заголовки (`after_request`): `X-Content-Type-Options: nosniff`,
  CSP `default-src 'self'; style-src 'self' 'unsafe-inline'`; для JSON-статуса
  `Cache-Control: no-store`. `errorhandler(Exception)` — без traceback в браузер.

## 2. Топология страниц (минимальный набор)

| Роут | Назначение |
|------|-----------|
| `/` | редирект на главную (галерею) |
| `/gallery?src=&cam=&date=&page=` | галерея карточек событий (24/стр) |
| `/video?date=` | таблица видеоархива по часам 00→23 (если архив есть) |
| `/panel` | статус системы (опционально; иногда галереи достаточно) |
| `/api/status` | JSON: счётчики, `gallery_ver`, `today` (для поллинга) |
| `/media/{kind}/<cam>/<date>/<file>` | раздача файлов (source для `<img>`/`<video>`) |
| `/view/{kind}/<cam>/<date>/<file>` | СТРАНИЦА-ПЛЕЕР (см. §5 — критично!) |

Навигация в шапке всех страниц: «Панель | Галерея | Видео». Всё остальное —
только если заказчик прямо просил.

## 3. Структура артефактов и связи

```
<save_folder>/
  clips/camN/<YYYY-MM-DD>/<имя>.mp4        # клипы событий (H.264!)
  photo/camN/<YYYY-MM-DD>/<имя>.jpg        # фото события = первый кадр клипа
  photo/camN/<YYYY-MM-DD>/<имя>_tb.jpg     # превью 320px, JPEG Q85 (PIL LANCZOS)
  trigger/camN/<YYYY-MM-DD>/<ts>.jpg       # артефакты второго типа (сырые кадры)
  trigger/camN/<YYYY-MM-DD>/<ts>_tb.jpg
<archive_folder>/camN/<YYYY-MM-DD>/<дата-время>.mp4   # непрерывный архив
```

- Имя файла = **метка времени события** (`YYYY-MM-DD_HH-MM-SS...`) — сортировка
  списка = сортировка по имени (`reverse=True` — новые сверху). Это избавляет
  от БД для галереи: дата-фильтр = имя папки, сканируй ТОЛЬКО `camN/<date>/`.
- Связь «фото ↔ клип» — по совпадению stem имени (фото пишется из первого кадра
  клипа с тем же именем). Кнопку «Клип» показывай, ТОЛЬКО если mp4 реально есть
  на диске (`os.path.isfile`) — никаких мёртвых ссылок.
- Превью `_tb.jpg` пиши **в writer-потоке события** (не в HTTP-потоке) через
  общий хелпер: `save_thumb(img_bgr, path, width=320, quality=85)` на PIL
  (`Image.init()` при старте в ГЛАВНОМ потоке: импорт плагинов PIL внутри
  worker-потока на Windows/Py3.14 давал fatal 0x80000003).
- Ротация/очистка артефактов — по паттерну `*.jpg`/`*.mp4` целиком: `_tb.jpg`
  должны удаляться вместе с оригиналами (проверь тестом).

## 4. Раздача файлов — безопасность обязательна

Один параметризованный гард на все `/media/*` и `/view/*`:

```python
_CAM_RE = re.compile(r"cam(\d+)$")            # папка камеры
_DATE_RE = re.compile(r"^\d{4}-\d{2}-\d{2}$") # папка даты
_FILE_RE = re.compile(r"^\d{4}-\d{2}-\d{2}_\d{2}-\d{2}-\d{2}.*\.jpg$", re.I)
_VIDEO_RE = re.compile(r"^\d{4}-\d{2}-\d{2}_\d{2}-\d{2}-\d{2}.*\.mp4$", re.I)

def _resolve_media(root, cam, date, filename, file_re):
    if not (_CAM_RE.fullmatch(cam or "") and _DATE_RE.fullmatch(date or "")
            and file_re.fullmatch(filename or "")):
        return None                       # -> 404
    path = os.path.join(root, cam, date, filename)
    root_abs = os.path.realpath(root)
    if not os.path.realpath(path).startswith(root_abs + os.sep):
        return None                       # traversal -> 404
    return path if os.path.isfile(path) else None
```

`send_file(path, conditional=True)` — Range-запросы (перемотка) werkzeug делает сам.
`Cache-Control: public, max-age=31536000, immutable` — для JPEG-артефактов (неизменяемы
по имени); для mp4 НЕ ставь immutable (ротация удаляет). Ссылки с `target="_blank" rel="noopener"`.

## 5. Видео: КРИТИЧНЫЕ ОШИБКИ (прожиты)

1. **XVID/MPEG-4 Part 2 (fourcc `XVID`, `mp4v`) браузеры НЕ проигрывают** (Chrome/Edge/Yandex —
   все Chromium). Симптом: «ссылки есть, видео не открывается». Пиши архив/клипы
   **H.264 (fourcc `avc1`)**. На Windows нужен OpenH264 dll рядом с программой
   (`openh264-*-win64.dll`) или MSMF-бэкенд. Фолбэк-цепочка писателя
   (fail-safe — не потерять запись): `avc1 → mp4v → XVID`, первый открывшийся
   `VideoWriter`; при откате — один warning в лог с фактическим кодеком.
2. **Прямая ссылка на `.mp4` в новой вкладке** в Yandex Browser открывает ПУСТУЮ
   вкладку (менеджер загрузок перехватывает навигацию к медиафайлу). Решение —
   всегда открывать видео через **страницу-плеер** `/view/...` с тегом
   `<video controls autoplay src="/media/...">`: теги `<video>` не перехватываются
   ни одним браузером. (Это же лечит разное поведение браузеров при прямом открытии.)
3. **Битый mp4 при закрытии программы**: `VideoWriter.release()` обязан вызваться.
   Паттерн остановки рекордера: рабочий поток на выходе дочищает хвост очереди
   (с лимитом по времени, ~2 с) и сам закрывает writer; `stop()` = `join(timeout)`
   + страховочный идемпотентный `_close_writer()`; остановку рекордеров вешай в
   `finally` главного цикла. НИКАКИХ вечных `while not queue.empty(): sleep()` —
   при `running=False` воркер уже не выгребает очередь, остановка зависает навечно.
4. **Текущий (пишущийся) сегмент архива не показывать** в списке (он битый до
   закрытия). Эвритика готовности: `mtime файла < now − 15 с`. Ссылка появляется
   после закрытия — событие из рекордера поднимает `gallery_ver` (§6).
5. **Сегменты архива резать по границам сетки часов** (от 00:00: `segment=60` → файлы
   закрываются в :00; `30` → :00/:30; `15` → :00/:15/:30/:45), а НЕ «через N минут
   от старта»: иначе файл 13:34 живёт до 14:34 и попадает в две строки таблицы часов.

```python
def _next_segment_boundary(start, seg_minutes):   # чистая функция, покрыть тестами
    midnight = start.replace(hour=0, minute=0, second=0, microsecond=0)
    step = seg_minutes * 60
    k = int((start - midnight).total_seconds()) // step + 1   # строго ПОСЛЕ start
    return midnight + timedelta(seconds=k * step)
```

## 6. Автообновление без F5 (паттерн «версия альбома»)

Никаких WebSocket/SSE. Один монотонный счётчик + существующий поллинг:

- `bump_gallery_version()` (потокобезопасно, под Lock; ленивый синглтон — безопасен,
  когда сервер не запущен) вызывается писателями после каждого СОХРАНЁННОГО
  артефакта (фото/клип/сегмент архива). Превью `_tb` — НЕ отдельное событие.
- `/api/status` отдаёт `"gallery_ver": N` и `"today": "YYYY-MM-DD"`.
- `dashboard.js`: поллинг раз в 2–3 с; при смене `gallery_ver` — `fetch(location.href)`
  и подмена `innerHTML` обёрнутого фрагмента (`<div id="gallery-content">` /
  `#video-content`; фильтры, `<dialog>`, скрипт — ВНЕ фрагмента). Открытый
  `<dialog>` — скипать тик (не закрывать просмотр у пользователя).
- **Смена дня в 00:00**: при `today` > запомненного — обновить `max` у
  `<input type=date>` и, ТОЛЬКО если пользователь смотрит «сегодня», перейти на
  новую дату (историю не переключать самовольно).

## 7. Галерея: карточки, фильтры

- Карточка (`figure.item`, `position:relative`): `<img loading="lazy" src="..._tb.jpg">`,
  подпись: чип типа → камера → дата-время; кнопка «▶ Клип» (см. §5.2) —
  `position:absolute` правый нижний угол + у подписи **`padding-right` по ширине
  кнопки** (иначе длинный текст уезжает под кнопку — жалоба №1 по UX).
- Чип типа события: цветом (Тревога — красный `#d9534f`/белый текст, датчик —
  жёлтый `#f1c40f`/тёмный). **Каскад CSS**: базовый стиль чипа (шрифт/геометрия)
  без `background`; цветные правила — селектором ВЫШЕ специфичностью
  (`.item .cap .type-alert{...}` — 3 класса против 2 базового) — иначе серый
  базовый фон перебивает цвет при равной специфичности (жалоба №2 по UX).
- Пагинация серверная 24/стр (`LIMIT/OFFSET` или срез списка по имени);
  фильтр типа — вкладками-ссылками `?src=all|alert|trigger`; фильтр камеры — `?cam=`.
- Фильтр по дате: `[‹] [input type=date, max=сегодня] [›]`; ‹ — минус день,
  › — disabled (`span`, не `<a>`) при `date >= сегодня`; все ссылки сохраняют
  `src/cam/date`, при смене даты `page=1`. Валидация даты: regex +
  `strptime`, мусор → сегодня (не падать!). Отдельный query `date` для
  видеоархива — та же логика, вынести общий хелпер.
- Пустое состояние — с датой: «Событий за 2026-09-28 нет».

## 8. Таблица видеоархива

- Строки часов **00:00 → 23:00 по возрастанию** (внимание: в галерее наоборот —
  новые сверху!); час берётся из имени файла (`name[11:13]`); внутри часа — по
  камерам/времени; пустой час — «—».
- Ссылки `.vlink` → `/view/video/...` (страница-плеер, §5.2).

## 9. Конфигурация и эксплуатация

- Секция конфига приложения: `enabled`, `host=127.0.0.1`, `port` (8080). Без пароля —
  при строгом localhost; иначе Basic Auth (base64 в `Authorization`) + честное
  предупреждение в конфиге про LAN.
- Защита от двойного запуска приложения-хозяина: именованный мьютекс Windows
  (`kernel32.CreateMutexW`, `GetLastError() == 183` → уже запущено; хэндл держать
  в глобали модуля). При падении процесса ОС освобождает мьютекс сама — никаких
  pid-файлов.
- Конфиги/требования — строго UTF-8 (UTF-16 ломает pip/configparser).
- Тесты не должны требовать сеть/камеры: Flask `test_client` без запуска сервера,
  артефакты — в `tmp_path` через фейковые файлы.

## 10. Чек-лист приёмки (прогнать обязательно)

1. `pytest` зелёный; отдельные тесты-ловушки: traversal (`..%2F..%2F`) → 404;
   чужое расширение в `/media` → 404; свежий (пишущийся) файл не показан;
   `test` на позицию цветных CSS-правил ПОСЛЕ базовых (ловит регрессию серых чипов);
   `test` границ сегментов (13:34→14:00; старт ровно на границе → следующая, без пустых);
   `test` `bump_gallery_version` → `/api/status` инкремент; страница-плеер содержит `<video`.
2. Живой smoke руками: открыть `/gallery`, кликнуть карточку (dialog), клип
   (плеер во вкладке — проверить ИМЕННО в браузере заказчика!), сменить дату,
   подождать 3 с после новой записи — карточка появилась без F5.
3. Перезапуск приложения посреди записи: битых mp4 не осталось (все сегменты
   открываются).
