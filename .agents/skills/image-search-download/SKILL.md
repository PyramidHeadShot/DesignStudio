# Поиск и скачивание изображений для агента

Проверено живыми сессиями 08–09.10.2026 (задачи: 4 модели мотоциклов, цель 30–50
обоев на модель, ≥1920x1080, 16:9). Bing Image Search API закрыт с 2025 — не
используй и не упоминай его. Скрейп HTML выдачи Bing через curl тоже НЕ работает
(отдаёт мусорные страницы). Порядок источников ниже — по реальной эффективности.

## Язык запросов — всегда английский

Поисковые запросы к источникам писать НА АНГЛИЙСКОМ: индексы и теги наполняются
англоязычными описаниями — «wallpapers» находит в разы больше, чем «обои».
Русские запросы — только если источник локально-русский и тема локальная.

## Соотношение сторон — 16:9 только (обязательное правило)

Обои для рабочего стола сохранять ТОЛЬКО с соотношением сторон 16:9 (1.778).
Допуск — ±1% на округление: `w/h` в диапазоне `[16/9*0.99, 16/9*1.01]`.
Проходят 1920x1080, 2560x1440, 3840x2160; НЕ проходят 4:3 (1920x1440!), 16:10
(2560x1600), 3:2 (3000x2000), портрет и квадрат — удалять независимо от разрешения.
Проверять ПОСЛЕ скачивания по фактическим размерам, а не по метаданным.
Плюс минимум: ≥1920x1080 (если не задано иное).

Практика: поисковики наверх отдают пресс-фото 3:2 и 4:3 — из обычной выдачи
16:9 проходит лишь ~10–20%. Поэтому главный источник — обои-сайты (ниже).

## Источник 1 (главный) — Google Images через браузер + site: на обои-сайты

Chrome DevTools MCP: navigate на `https://www.google.com/search?q=<запрос>&tbm=isch&tbs=isz:lt,islt:2mp&udm=2`
(«больше 2MP»), затем вытащить URL оригиналов из DOM скриптом:

```js
// evaluate_script по document.documentElement.innerHTML
// regex: /https?:\/\/[^\s"'()<>\\]+/g; исключить gstatic;
// оставить .jpg/.jpeg/.png/.webp; сохранить результат через filePath (не в контекст!)
```

- `site:wallpapercat.com "<модель>"` — САМЫЙ результативный приём: в full-URL
  зашиты и модель (слаг `...-street-bob-...`), и точный размер
  (`...-1920x1080-desktop-...`) → пре-фильтр 16:9 прямо по URL до скачивания.
- Слаг в URL = проверенная релевантность (ищи `<model>` в слаге, отсеивай generic).
- Варианты запросов: модель + `wallpaper`, модель + `press photo`, модель + год.
- Одна выдача ~75–100 URL; для объёма делай 2–3 разных запроса.
- Внутри wallpapercat-поиска (`/search?term=...`) результаты грузятся лениво:
  надёжнее собирать `a[href*="/w/full/"]` из DOM после полной загрузки.

## Источник 2 — Yandex Images через браузер

`https://yandex.ru/images/search?text=<запрос EN>&isize=large&aspect=wide`

- **Не верь `isize=exact&iszw=1920&iszh=1080`**: фильтр часто подсовывает 4:3
  (1920x1440) под видом точного размера. `aspect=wide` честнее.
- Оригиналы сидят в JSON страницы с HTML-сущностями (`&quot;`) — обязательно
  `html.unescape()`, иначе curl получит битые URL.
- Превью-паттерн goodfon: `/wallpaper/nbig/` → замени на `/wallpaper/original/`.

## Источник 3 — wallhaven.cc (без ключа для SFW)

```
GET https://wallhaven.cc/api/v1/search?q=<тема>&at_least=1920x1080&ratios=16x9&purity=100
```

- `ratios=16x9` — встроенный фильтр сторон; `at_least=`, `resolutions=`.
- НИшевые модели мотоциклов: почти всегда 0 результатов (проверено на 3 моделях
  Harley/Yamaha). Годится для широких тем (города, природа, anime).
- Ответ: `data[].path` (прямой файл), `data[].resolution`. `purity=100` — только SFW.

## Источник 4 — Wikimedia Commons (чистые лицензии)

```
GET https://commons.wikimedia.org/w/api.php?action=query&generator=search&gsrnamespace=6&gsrsearch=<тема>&gsrlimit=50&prop=imageinfo&iiprop=url|size&format=json
```

- **Обязательно `gsrnamespace=6`** — иначе мусор из статей.
- Фильтруй по заголовку (title должен содержать модель) — поиск по теме тянет
  нерелевантное (на «Street Bob» пришли Knucklehead 1941 и памятники байкерам).
- Большинство фото 3:2/4:3 → под 16:9 почти не годятся, но лицензии чистые.
- User-Agent обязателен.

## Источник 5 — Openverse (CC, агрегатор)

`GET https://api.openverse.org/v1/images/?q=<тема>&size=large&page_size=20`
По специфичным моделям — 0 результатов (проверено). Для коммерции — с токеном.

## Ключевые (для коммерции) — если есть ключ

- **Pixabay**: `min_width`/`min_height` в фильтрах, коммерция без атрибуции.
- **Unsplash / Pexels**: ключ бесплатный, `orientation=` фильтр.

## Паттерн скачивания (проверяй всегда!)

1. **Полный размер**:
   ```
   curl -sL --max-time 15 -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64)" -e "<источник>" -o file.jpg "<url>"
   ```
   User-Agent обязателен (hotlink-защита); Referer — по хосту (wallpapercat — свой сайт, google — универсально).
2. **Проверка magic bytes** (первый байт): JPEG = `FF D8`, PNG = `89 50 4E 47`,
   WebP = `RIFF....WEBP`. HTML/текст — удалить. (Практика: 20–30% ссылок — заглушки.)
3. **Фактические размеры** (PowerShell, не верь метаданным/URL):
   ```powershell
   Add-Type -AssemblyName System.Drawing
   $img = [System.Drawing.Image]::FromFile($path)  # $img.Width / $img.Height
   ```
   Скрипт за один проход: magic bytes + размеры → отчёт `OK|path|WxH` / `BAD|path`.
4. **Дедуп по размеру файла** (`os.path.getsize`) — коллизии байт-в-байт = один и тот
   же кадр из разных выдач. Считать и уже лежащие в папке.
5. **Вежливость**: пауза 0.2–0.5 c между curl; на 429 — `Retry-After` или бэкофф 2/4/8 c.
6. **Не читать картинки в контекст сессии** (лимит изображений провайдера — скилл
   `image-context-limits`). Всё проверять скриптами и текстовыми отчётами.

## Грабли окружения (реальные, экономят часы)

- **CRLF ломает curl**: файл URL, записанный python'ом по умолчанию, содержит
  `\r` → `curl: (3) URL rejected: Malformed input`. Пиши списки с
  `open(..., 'w', newline='\n')` или срезай `u="${u%$'\r'}"` при чтении в bash.
- **Self-truncation**: `tr < file > file` и вообще `cmd < X > X` (в т.ч. по одному
  пути через разные имена каталогов) — обнуляет вход. Выход всегда в ДРУГОЙ файл.
- **Файлы, созданные bash в /tmp, могут не переживать вызов инструмента** — списки
  URL пиши из python в Windows-путь (Temp), их bash читает надёжно. `/tmp` в bash
  = `C:\Users\<user>\AppData\Local\Temp` (python оттуда же читает).
- **Длинные циклы скачивания** бей на вызовы по 1–2 мин с докачкой:
  `[ -s "$f" ] || curl ... -o "$f"` — пропуск уже скачанных непустых.
- **python в окружении — виндовый**: путей `/tmp/...` он не понимает, только `C:\...`.
  Вывод в консоль может падать на кириллице (cp1251) — пиши латиницей или в файл.
- HTML-сущности в вытащенных URL (`&quot;`, `&amp;`) — обязательный `html.unescape`.

## Структура результата

- Файлы вида `<Model> NN.jpg` (01…N без дыр; при дозаполнении нумерацию продолжать).
- Рядом `SOURCE.txt`: источник каждого файла (`имя | WxH | URL`) + пометка
  «для личного использования». Обновлять при дозаполнении, чистить записи удалённых.
- Временные файлы (json URL-листы и т.п.) из папки проекта — удалять.

## Лицензии — кратко

- Личное использование (обои себе) — любой источник, включая поисковики и wallpapercat.
- Публикация/коммерция — только Commons (CC/PD), Openverse (`license_type=commercial`),
  Pixabay/Unsplash/Pexels; wallhaven — осторожно, per-image.
- CC BY / BY-SA требуют атрибуции (автор + лицензия + ссылка); CC0/PD — нет.

## Рабочий рецепт (агенту, сжато)

```
0. Цель: N обоев ≥WxH, 16:9 ±1%. Папка + SOURCE.txt.
1. Старые пулы: если временные загрузки прошлых сессий живы — пере-фильтруй их
   по 16:9 прежде чем искать заново (бесплатный прирост).
2. Основной заход: Google Images (браузер) с site:wallpapercat.com "<model>"
   → URL со слагом модели и размером → пре-фильтр 16:9 по URL → скачать.
3. Добор: Google "<model> wallpaper"/"press photo" (tbs=isz:lt,islt:2mp) +
   Yandex aspect=wide; Commons с фильтром по title; wallhaven ratios=16x9.
4. Скачать (UA+Referer, пауза) → magic bytes → PowerShell размеры →
   16:9 и ≥минимума → дедуп по размеру файла → скопировать до цели.
5. Удалить несоответствующие; обновить SOURCE.txt; убрать временные файлы.
6. Финальный проход PowerShell по всем папкам: OK/BAD — BAD не оставлять.
```
