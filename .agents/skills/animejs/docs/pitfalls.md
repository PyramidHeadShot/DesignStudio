# Грабли anime.js v4 на этом проекте

## Тайминги и монтирование

- Astro-скрипты — ES-модули: исполняются после парсинга HTML, но шрифты и
  картинки могут ещё не готовы. Анимации, зависящие от метрик (FLIP, layout),
  запускать после `document.fonts.ready` / полной загрузки островка, иначе
  снимешь снапшот позиций до загрузки шрифта — все дельты «поедут».
- `astro:after-swap` после View Transitions: старые анимации продолжают жить в
  движке и тикают по невидимым узлам. Каждый островок обязан держать свой
  `scope` и делать `revert()` на swap (рецепт №6). Без этого — утечки и «зомби»-твины.
- Не навешивать анимации на элементы, которые ещё `hidden`/`display: none`:
  v4 снимет нулевые/сбитые стартовые значения, при появлении будет скачок.
  Стартовые состояния ставить в момент видимости.

## Layout thrash

- Анимировать можно `transform` (поля `translateX/Y`, `rotate`, `scale`…),
  `opacity`, `clip-path`, цвета, фильтры. `width/height/top/left/margin/padding`
  = reflow каждый кадр = гарантированные просадки на мобилках. Если уж нужен
  layout-переход — только `createLayout` (FLIP-снапшот) или ручной FLIP
  (рецепт №2б).
- Не смешивать в одном кадре чтение метрик (`getBoundingClientRect`, `utils.get`)
  и запись через анимации на большом числе элементов — batching:
  сначала все чтения, потом все мутации.
- Стартовые состояния из JS (`utils.set`), не из CSS: без JS сайт остаётся
  читаемым, а с JS не будет «вспышки» (FOUC) — но ставить их как можно раньше
  в скрипте, до первого кадра анимации.

## Утечки памяти и revert

- `createScope().add(fn)` без cleanup-функции: listeners, подписки, интервалы
  (в т.ч. `IntersectionObserver` из рецепта №4) останутся жить после `revert()`.
  Возвращай из `add(fn)` функцию с `io.disconnect()` и прочими отменами.
- `loop: true` без `alternate` на элементах ниже вьюпорта — вечные тики CPU.
  Для scroll-зависимых — `autoplay: onScroll(...)`, чтобы останавливалось вне экрана.
- `persist` (default `false`): после `complete()` inline-стили остаются как
  есть у renderable; `revert()` откатывает inline-стили. При демонтаже секции
  — `revert()` обязательный, иначе inline `transform` прилипнет к клонированным
  при swap узлам.

## Браузеры и среда

- v4 требует современных браузеров (ES2020+, `transform` через отдельные поля
  на `style`). Для устаревших целей не полифиллится — гарантия: контент виден
  без JS (правило progressive enhancement), анимации просто не начинаются.
- WAAPI-мост (`waapi.animate`) завязан на браузерный `Element.animate` —
  поддержка та же, что у Web Animations API; использовать точечно.

## Бандл и вес (бюджет проекта ≤ 25 КБ gzip)

- Замер (esbuild --bundle --minify, gzip): базовый набор
  `animate + createTimeline + createTimer + stagger + onScroll + createScope + utils`
  = **21,5 КБ gzip**. С `svg + text + createLayout` = **34,5 КБ gzip** — за бюджетом.
- Значит: svg-модули (`createDrawable`, `morphTo`, `createMotionPath`) и
  `text.splitText` подключать только на страницах, где они реально нужны
  (разделение по островкам), либо осознанно перерасходовать бюджет с заказа.
- Импортируй named-функциями (`import { animate } from 'animejs'`) —
  subpath-экспорты ('animejs/svg', 'animejs/text', …) тоже поддерживаются,
  tree-shaking работает на обоих путях.

## SSR / Astro static

- Static-страницы Astro рендерятся без JS — сама библиотека в SSR-бандл не
  попадает, проблем гидрации нет. Но: клиентский `<script>` в компоненте
  исполняется у всех пользователей — не запускать тяжёлую инициализацию анимаций
  до `DOMContentLoaded`/видимости и не тащить скрипт в head.
- Не вызывать `utils.get`/анимации на этапе серверного рендера: `document`
  отсутствует — весь анимационный код строго внутри клиентских скриптов.

## Типичные ошибки API (проверено по .d.ts v4.5.0)

- v3-синтаксис (`anime({...})`, `anime.stagger`, `anime.random`, `easing:`)
  в v4 не существует — см. секцию «НЕ делать» в SKILL.md.
- `seek()` принимает только число (мс), не строку `'50%'` — проценты через
  `anim.currentTime = anim.duration * 0.5`.
- Позиция timeline `'<'` — это КОНЕЦ предыдущего элемента, `'<<'` — НАЧАЛО.
  В народных скиллах встречается перепутанное описание — верить только
  `docs/api-cheatsheet.md` (сверено с types/index.d.ts).
- Функция-based values — только внутри value-слотов свойств; второй аргумент
  `animate(targets, params)` — всегда объект параметров.
- Анимация `transform` строкой не работает — только отдельные поля.
