# AGENTS.md — точка входа агента

Универсальный роутер. Подходит любому проекту; детали — по ссылкам в `.ai/`, читай их по мере необходимости, не всё сразу.

## Инфраструктура устройств

Когда пользователь говорит «ПК», «НОУТ», «NEO», «IPHONE» — это машины экосистемы:
**адреса, роли и сетевые факты — в `.ai/INFRASTRUCTURE.md`** (Tailscale-IP, SSH, сеть). Сверяйся с ним, не угадывай.
**Привязка проектов к машинам:** перед правками в любом проекте проверь `hostname` и таблицу
«Привязка проектов к машинам» в `.ai/INFRASTRUCTURE.md` (или метку «Машина-хозяин» в AGENTS.md проекта).
Проект закреплён за другой машиной → НЕ править и НЕ удалять ничего в его папке (правки через синк
рушат работу) — выполнить задачу на машине-хозяине или сказать пользователю.

## Железные правила

1. Сначала читай, потом пиши: изучи файл и его использований до правки.
2. Минимальный дифф: не переформатируй и не трогай код вне задачи.
3. Секреты не коммитить и не выводить целиком; они в gitignored `.env`.
4. Не запускай долгоживущие сервисы без явной просьбы; для диагностики — логи.
5. Не расширяй скоуп молча: нашёл смежную проблему — сообщи.
6. Неоднозначно и ошибка дорога — задай один конкретный вопрос, а не угадывай.
7. После правок — проверка (компиляция/тесты/линтер); не можешь проверить — скажи явно.
8. Сообщение вида «Вопрос: текст» — режим «только ответ»: ответь на вопрос без правок кода,
   изменений файлов и действий с проектом (установки, запусков). Только пояснение и,
   при необходимости, список вариантов или рекомендаций.

Полная версия: `.ai/rules.md`.

## Протокол маршрутизации: локальный или облачный агент

**Каскад дирижёр–исполнитель (2026-09-28):** главная модель — дирижёр `glm-5.3-flash`:
быстро читает запрос, выдаёт короткий план/маршрут, декомпозиция, ревью. Массовую проработку
(код, вёрстка, длинные файлы, перебор, суммаризация) первым делом отдавай субагенту
`cloud-mimo` (mimo-v2.6-flash — дежурный рутины, копеечное чтение кэша) или локальным
агентам (`local-worker*`). Эскалация средней сложности — специалист `mimo-v2.6-pro`
(субагент `cloud-mimo-pro`): если flash галлюцинирует или не справляется с логикой. Сам делай только точечные правки,
инструкции и финальное ревью; длинные артефакты не тяни в свой контекст — проси исполнителя
вернуть краткое резюме; свои ответы держи короткими.
**Дежурный исполнитель:** держи одну накапливающую сессию `cloud-mimo` и передавай ей задания
через `resume` её последнего run-id (id меняется после каждого resume — отслеживай), а не новым
спавном: контекст проекта копится, а не сбрасывается. Память-источник — файлы (PROJECT.md,
Задачи.md): сессия может сжиматься, файлы — нет. Для переживания смены машины реестр прогонов
синкается через `PI_SUBAGENTS_TEMP_ROOT` → `.pi/subagents-temp` (ПК настроен, НОУТ — см.
Задачи.md); run-id дежурного держи в Задачи.md. Прогоны, созданные ДО выставления переменной,
живут в temp машины и между машинами не резюмятся. Resume дежурного работает ТОЛЬКО внутри сессии, его запустившей (эксперимент 2026-09-26: из чужой сессии pi отвечает «not found in the active session»). Новая сессия или другой проект заводит СВОЕГО дежурного и поднимает знания из файлов (PROJECT.md, Задачи.md, skills) — это штатная норма, не ошибка. Форма resume: ВСЕГДА передавай `dir` = полный путь run-папки дежурного (`.pi/subagents-temp/async-subagent-runs/<run-id>`) — без него цепочка «не находится» даже у родной сессии («Async run not found»). Ретеншн при этом ни при чём: он удаляет только прогоны старше 30 дней (лог: `async-retention-maintenance.jsonl`).
**Синк комплекта в проекты (обязательно, урок 06.10):** изменил любой комплектный файл кита
(`.pi/` — особенно `.pi/agents/`, `.ai/`, `.agents/skills/`, `scripts/`, AGENTS.md) — сразу прогони
`node scripts/kit-drift.mjs` (найдёт отставшие проекты-соседи) и обнови их
`node scripts/kit-sync.mjs <проекты>`. Проект чужой машины — НЕ синкать через общую папку:
запиши хвост в Задачи.md и обнови на машине-хозяине. «Синкнется сам» — не работает: синк только ручной.

Оценивай каждую входящую задачу и маршрутизируй:

- **Мелкая рутина** (скан папки, подсчёты, поиск TODO, конспект, простая механическая правка) —
  делегируй `local-worker-xl` сам, без вопроса, и отчитайся его результатом. При сомнении в
  качестве — перепроверь сам или переделай.
- **Сложные задачи** (архитектура, рефакторинг, отладка логики, финальные ревью, интернет-факты) —
  выполняй сам на облачной модели.
- **Крупные или неоднозначные** — предложи пользователю: «рутинную часть отдать local-worker-xl?» —
  запуск только после согласия.
- Для глубокого анализа, где важно качество, но задача механически объёмна — `local-worker-xl`
  (27B, медленнее, но точнее).

Если поступившая задача (или её часть) подходит для офлайн-модели — сканирование,
каталогизация, поиск TODO/дублей, черновой обзор, простые механические правки,
конспекты, генерация тестовых данных — **сам предложи пользователю**:

> «Эта задача подходит для локального `local-worker` (офлайн, без расхода квоты) — запустить его?»

- Запускай только после явного согласия пользователя.
- Подходит ли задача — решай по её природе, а не по размеру: рутинный перебор/классификация — да;
  архитектура, тонкий рефакторинг, финальные ревью, интернет-факты — нет.
- Смешанная задача: отдай local-worker рутинную часть, сам делай содержательную.

## Если `.ai/PROJECT.md` отсутствует

Ты в новом/неописанном проекте: выполни онбординг (`.ai/playbooks/bootstrap.md`) и создай карточку. Занимает 2–3 минуты, дальше экономит время каждый раз.
