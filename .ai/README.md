# .ai — служебная папка ИИ-агента

Комплект для работы любого кодинг-агента (pi, Codex, Cursor, Gemini CLI и др.) в любом проекте. Композиция: `AGENTS.md` (корень) + эта папка (+ опционально `.pi/`). Содержимое для агента описано в [INDEX.md](INDEX.md) — этот README для вас, человека.

> 📖 Пошаговые сценарии установки — [УСТАНОВКА.md](../УСТАНОВКА.md): чистый компьютер (установка pi), новый проект, внедрение в существующий.

## Установка в проект

```bash
cp -r AGENTS.md .ai .pi .agents /путь/к/проекту/
```

- `AGENTS.md` автоматически читается агентами (pi — из коробки; остальные — по конвенции agents.md или через первый промпт «прочитай AGENTS.md»).
- `.pi/` — опционально, только для pi: субагенты и MCP-серверы. Требует `pi install npm:pi-subagents npm:pi-animations npm:pi-tps-was-taken` (MCP встроен в pi 0.99+); подробности — `.pi/README.md`.
- Для ssh/sftp-агентов: скопируй `.env.example` → `.env` и заполни креды (gitignored).

## Что происходит дальше

| Сценарий | Поведение агента |
|----------|------------------|
| **Новый пустой проект** | Поможет выбрать стек и создать каркас; `.ai/PROJECT.md` заполнит по ходу работы реальными фактами |
| **Существующий код** | Пройдёт онбординг (`playbooks/bootstrap.md`) и сам создаст `.ai/PROJECT.md` — карточку проекта (стек, команды, env, подводные камни) |
| **«Составь список задач»** | Агент запишет предложения в `Задачи.md` (корень, из `templates/ZADACHI.md`), а не только в чат; вы дополняете его сами, агент отмечает выполненное |

Проверить результат: попросите агента «пройди онбординг» и посмотрите `.ai/PROJECT.md`.

## Ваши файлы в корне проекта

Эти файлы создаёт и поддерживает агент, но ведёте их вы — они написаны для людей:

| Файл | Что это | Кто заполняет |
|------|---------|---------------|
| `Описание.md` | Пользовательская документация: возможности, установка, версии | Вы и агент; при новой версии агент добавляет секцию (`playbooks/release.md`) |
| `Задачи.md` | Бэклог: открытые / готовые / отложенные задачи | Вы пишете сами или просите агента; агент отмечает выполненное и записывает туда списки улучшений |

Оба шаблона — в `templates/` (`OPISANIE.md`, `ZADACHI.md`); при онбординге агент сам предложит их создать, если файлов нет.

## Состав `.ai/`

| Файл | Для чего |
|------|----------|
| `INDEX.md` | Карта папки для агента: файл → когда читать |
| `rules.md` | Правила поведения: границы, секреты, скоуп |
| `workflow.md` | Цикл работы над задачей |
| `playbooks/` | Пошаговые сценарии: онбординг, тесты, отладка, коммиты |
| `templates/` | Шаблоны: `PROJECT.md` (карточка для агента), проектный `AGENTS.md`, пользовательские `Описание.md` и `Задачи.md` |
| `PROJECT.md` | Появляется в проекте — живая карточка проекта (стек, команды, env, подводные камни) |

### Состав `.pi/` (только для pi)

| Файл | Для чего |
|------|----------|
| `README.md` | Как включить: пакеты, trust, формат агентов, адаптация под проект |
| `mcp.json` | MCP-серверы проекта (chrome-devtools, ssh-connect, sftp-connect) |
| `agents/*.md` | Субагенты: browser-checker, docs-maintainer, html-designer, test-runner, test-fixer, server-operator, sftp-operator, server-deployer |
| `scripts/ssh.sh`, `scripts/sftp.sh` | Обёртки MCP, читают креды из gitignored `.env` |
| `scripts/kit-install.mjs` | Установка комплекта в проект (защита проектных файлов, флаги `--no-pi`, `--no-ssh`) |
| `scripts/kit-sync.mjs` | Обновление комплекта в проектах из мастер-копии |
| `scripts/kit-validate.mjs` | Проверка: frontmatter агентов, JSON, битые ссылки, CRLF |

## Обновление комплекта

1. **Централизованно**: правьте файлы здесь (мастер-копия), затем синхронизируйте в проекты скриптом:
   ```bash
   node scripts/kit-sync.mjs /путь/к/проекту1 /путь/к/проекту2
   ```
   Обновит `.ai/`, `.agents/` (skill-installer), `.pi/`, `scripts/`, `УСТАНОВКА.md`; обновит каталог `REGISTRY.md` свежими данными, сохранив журнал установок проекта. **Не тронет**: `.ai/PROJECT.md`, `Задачи.md`, `Описание.md`, `.env`, ваш `AGENTS.md` (при отличии появится `AGENTS.kit.md`).
2. **Вручную**: `cp -r AGENTS.md .ai .pi .agents /путь/к/проекту/` — но скрипт безопаснее (защита проектных файлов встроена).
3. **Проверка целостности**: `node scripts/kit-validate.mjs .` — frontmatter агентов, JSON, битые ссылки, CRLF. Полезно перед коммитом.
4. `.ai/` и корневые файлы коммитьте в git проекта — это командный артефакт, а не личный кэш. Секретов там нет по правилам `rules.md`.

## Принципы

- **Прогрессивная загрузка**: агент читает ~30 строк правил, углубляется по ссылке только когда задача требует.
- **Нет дублирования**: каждый факт — в одном файле, остальное — ссылки.
- **Портируемость**: в универсальных файлах нет ничего проектного; всё проектное — в `PROJECT.md`.
- **Разделение аудиторий**: для агента — `.ai/`, для людей — `Описание.md` и `Задачи.md`.
