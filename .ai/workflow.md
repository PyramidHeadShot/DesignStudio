# Workflow: порядок работы над задачей

## 1. Понять

- Перечитай запрос; выпиши: что должно измениться, как проверить результат.
- В корне есть `Задачи.md` → открытые задачи там — первоочередной источник работы; результат анализа («что улучшить/исправить») записывай туда, а не только в чат.
- Чего-то не хватает в проекте → `.ai/playbooks/bootstrap.md`.

## 2. Спланировать

- Задача тривиальна (1–2 файла, понятная правка) → делай сразу.
- Иначе: короткий план (шаги, затрагиваемые файлы, способ проверки) → при неоднозначности согласуй с пользователем.

## 3. Реализовать

- Сначала изучи затрагиваемый код, потом правь.
- Один логический шаг = один блок изменений; не смешивай unrelated правки.
- Массовую работу делегируй исполнителям (`cloud-mimo` / `local-worker*` — см. `AGENTS.md` →
  «Протокол маршрутизации»); дирижёр делает точечные правки и ревью. От исполнителя проси
  краткое резюме, а не полный дамп — экономь токены обеих моделей.

## 4. Проверить

- Минимальная проверка: компиляция/линтер/тесты — команды из `.ai/PROJECT.md`.
- Проверь, что не сломал смежное: поиск использований изменённых символов.

## 5. Отчитаться

Формат: что сделано (пути файлов) → как проверено (команда + результат) → что осталось / риски.

## После изменений

- Обнови затронутые файлы `.ai/` и `AGENTS.md`, если изменились команды, структура или соглашения.
- Выполнил пункт из `Задачи.md` → отметь статус в том же коммите (правила — в шапке файла).
- Есть `Описание.md` и изменения заметны пользователю (функции, интерфейс, команды запуска) → обнови его по правилам `playbooks/release.md`.
- Коммит — по `.ai/playbooks/release.md` (если пользователь просит фиксацию).
