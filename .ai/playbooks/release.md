# Playbook: коммиты, ветки, релиз

## Коммит

- **Conventional Commits**: `type(scope): краткое описание в императиве (ГГГГ-ММ-ДД)`
  - types: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `perf`
  - **дата в конце сообщения обязательна**: пример — `feat: add wol server (2026-09-22)` — видно возраст изменения без git log
  - пример: `fix(auth): reject expired tokens with 401`
- Один коммит = одна логическая цель. Непроверенные/временные файлы не коммитить.
- Сообщение на английском (если пользователь не попросил иначе).
- Перед коммитом: `git diff --staged` — ревью собственного диффа, мусор убрать.

```bash
git add <файлы точечно>      # не git add -A по привычке
git commit -m "type(scope): описание"
```

## Ветки

- От актуального `main`/`master`: `git pull` → `git switch -c <type>/<кратко>` (напр. `fix/expired-token`).
- Работаешь в чужой ветке без явной просьбы → не пушь в неё.

## Перед PR / завершением

1. Тесты и линтер зелёные (команды из `.ai/PROJECT.md`).
2. Обновлены `.ai/PROJECT.md` и документация, если менялись команды/структура.
3. Описание PR: что, зачем, как проверялось.

## Описание.md (пользовательская документация)

Если в проекте есть `Описание.md` (путь — в `.ai/PROJECT.md`):

- **Новая версия** (изменилось то, что видно пользователю: функции, интерфейс, установка/запуск) → добавь секцию версии сверху: `<X.Y.Z> — <дата>`, список изменений языком пользователя, без технических деталей. Правишь в том же коммите, что и версию.
- Изменилось то, что описано в существующих секциях (установка, возможности) → обнови их на месте, не заводя секцию версии.
- Внутренний рефакторинг/фиксы, не видимые пользователю → `Описание.md` не трогай.
- Нет `Описание.md`, а проект уже публичный/переиспользуемый → предложи создать по `templates/OPISANIE.md`.

## Задачи.md

`Задачи.md` в корне — бэклог, который ведёт пользователь и агент (правила — в шапке файла, шаблон — `templates/ZADACHI.md`):

- Выполнил задачу оттуда → отметь `[x]` с версией/датой в том же коммите, что и изменения.
- Пользователь просит составить список задач/улучшений → пополни `Задачи.md`, а не только чат.
- Если файла нет → предложи создать по шаблону.

Граница: `Описание.md` — для пользователей проекта; технический контекст для агента — только `.ai/PROJECT.md`, дублировать его туда не нужно.

## Публикация

Деплой/релиз — только по явной просьбе пользователя и по процедуре проекта (если описана в `.ai/PROJECT.md` → «Деплой»).
