# Установка комплекта agent-starter-kit

Инструкция для человека. Описывает три сценария: установка pi с нуля, новый проект, внедрение в существующий проект.

Комплект лежит в этой папке:

| Что | Где |
|-----|-----|
| Роутер для агента | `AGENTS.md` |
| Контекст для агента (любой harness) | `.ai/` |
| Субагенты и MCP (только pi) | `.pi/` |
| Универсальные скиллы (любой агент) | `.agents/` |
| Креды для ssh/sftp-агентов (шаблон) | `.env.example` |
| Скрипты установки/синхронизации/проверки | `scripts/kit-install.mjs`, `kit-sync.mjs`, `kit-validate.mjs` |
| Эталон пользовательской папки pi | `dot-pi-agent/` (см. её `README.md`) |

---

## Сценарий 1 — чистый компьютер: установка pi с нуля
### Шаг 1. Node.js и git

Установите (ставит пользователь, руками):

- **Node.js LTS (20+)**: https://nodejs.org или `winget install OpenJS.NodeJS.LTS` (Windows) / `brew install node@22` (macOS). Проверка: `node -v` → v20+
- **git**: https://git-scm.com или `winget install Git.Git` / `brew install git`. Проверка: `git --version`

### Шаг 2. Запустить интерактивный установщик

Скопируйте папку `agent-starter-kit` себе (куда угодно) и запустите:

- **Windows:** двойной клик `УСТАНОВКА\УСТАНОВКА.bat`
- **macOS:** двойной клик `УСТАНОВКА\УСТАНОВКА.command` (если скачан — сначала `chmod +x УСТАНОВКА/УСТАНОВКА.command`)
- **Linux / терминал:** `node УСТАНОВКА/setup.mjs`

В меню выберите **«1 — Чистая установка»**. Мастер с вашего подтверждения на каждом шаге:

1. проверит Node.js ≥ 20 и git (если нет — даст точную команду под вашу ОС)
2. установит pi глобально: `npm install -g --ignore-scripts @earendil-works/pi-coding-agent`
3. перенесёт `dot-pi-agent/` → `~/.pi/agent` (Windows: `C:\Users\<USER>\.pi\agent`) — существующие файлы: бэкап + вопрос
4. поставит пакеты: `pi install npm:pi-subagents npm:pi-animations npm:pi-tps-was-taken`
5. напомнит вписать свой API-ключ в `~/.pi/agent/models.json`

Что именно делает мастер и что нужно до запуска — `УСТАНОВКА/README.md`.

<details><summary>Ручная установка (если мастер недоступен)</summary>

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
# первый запуск pi создаст ~/.pi/agent (пройдите стартовый диалог, выйдите /exit)
# скопируйте файлы из dot-pi-agent/ в ~/.pi/agent (структура — в dot-pi-agent/README.md)
pi install npm:pi-subagents
pi install npm:pi-animations
pi install npm:pi-tps-was-taken
```

> **Примечание pi 1.0.1+:** npm-установка больше не пинит транзитивные зависимости пакета
> (shrinkwrap убран), и `pi update` рекомендует установщик с **pi.dev** — с закреплёнными
> зависимостями. Наш мастер пока ставит через npm; миграция на pi.dev-инсталлятор — отдельным решением.

⚠️ **`models.json` — место для ваших API-ключей.** В комплекте ключи замаскированы (`************************`). Впишите вместо них реальный ключ вашего провайдера (образец структуры — `models.example.json`). Ключи — секреты: не коммитить, не пересылать; при передаче комплекта маскируйте их обратно.

</details>

#### Команды обновления pi

```bash
# 1) Обновить расширения (пакеты pi)
npm_config_allow_remote=all pi update --extensions

# 2) Обновить сам pi
npm_config_allow_remote=all pi update --self

# 3) Обновить pi + расширения + модели разом
npm_config_allow_remote=all pi update --all
```

**Примечания:**

- Префикс `npm_config_allow_remote=all` — страховка от блокировки remote-тарболов у зависимостей пакетов (когда-то это касалось `pi-mcp-adapter`; пакет больше не используется — MCP встроены в pi 0.99+).
- Если команда выполняется не в Windows CMD, а в PowerShell, задайте переменную так:

  ```powershell
  $env:npm_config_allow_remote="all"
  pi update --extensions
  ```

### Шаг 3. Проверка установки

Запустите `pi` вне проекта и проверьте:

- `/model` — видна модель из `models.json` (например, провайдер `provod`);
- `/mcp` — панель MCP открывается (серверов пока нет — это нормально, они проектные);
- русская справка на месте (расширение `russian-help.ts` загрузилось).

Либо пункт 4 мастера (`node УСТАНОВКА/setup.mjs`): проверка + обновление `~/.pi/agent` из комплекта.
Обновляются `settings.json`, `models.json`, `APPEND_SYSTEM.md`, `extensions/pi-tui-animations.json`;
ключи провайдеров и личный выбор (модель, тема) не трогаются, бэкапы `.bak-<время>` кладутся рядом с файлами.

### Шаг 4. (Опционально) Chrome для браузерных агентов

Агент `browser-checker` подключается к Chrome по CDP (`127.0.0.1:9222`). Надёжнее всего — отдельный экземпляр Chrome на **изолированном профиле** (не конфликтует с повседневным браузером и не заблокирован им):

```bash
"C:\Program Files\Google\Chrome\Application\chrome.exe" --profile-directory="Profile 2" --remote-debugging-port=9222 --user-data-dir="C:\temp\chrome-debug\1"
```

Удобно завести ярлык «Chrome Для Агента» на рабочем столе (PowerShell создаст его одной командой):

```powershell
$s=(New-Object -ComObject WScript.Shell).CreateShortcut("$env:USERPROFILE\Desktop\Chrome Для Агента.lnk"); $s.TargetPath="C:\Program Files\Google\Chrome\Application\chrome.exe"; $s.Arguments='--profile-directory="Profile 2" --remote-debugging-port=9222 --user-data-dir="C:\temp\chrome-debug\1"'; $s.Save()
```

Проверка, что CDP жив:

```bash
curl http://127.0.0.1:9222/json/version   # должен ответить JSON с версией Chrome
```

Простой вариант без изоляции — `chrome.exe --remote-debugging-port=9222` (работает, но конфликтует с уже запущенным Chrome обычного профиля).

### Шаг 5. Подключить шаблон к проекту

Дальше — сценарий 2 (новый проект) или 3 (существующий).

## Сценарий 2 — pi установлен, новый проект с нуля

### Шаг 1–2. Каркас + установка комплекта (одним шагом)

Можно через мастер: `node УСТАНОВКА/setup.mjs` → **«2 — Установить комплект в новый/пустой проект»** (создаст папку, сделает `git init`, скопирует комплект, обновит `REGISTRY.md`).

Или вручную:

```bash
mkdir my-project && cd my-project
git init
node <путь>/agent-starter-kit/scripts/kit-install.mjs .
cp <путь>/agent-starter-kit/.env.example .   # если нужны ssh/sftp-агенты
```

### Шаг 2. Креды (если нужны ssh/sftp)

`.env.example` → `.env`, заполнить `SSH_HOST/PORT/USER/PASSWORD`. Убедитесь, что `.env` в `.gitignore` (добавьте, если нет):

```gitignore
.env
```

> Как это устроено и когда файл вообще не нужен — см. раздел [«Как работают `.env.example` и `.env`»](#как-работают-envexample-и-env) ниже.

### Шаг 3. Первый запуск в проекте

```bash
pi
```

Pi спросит доверие к папке (trust) — подтвердите. Без trust проектные `.pi/`-ресурсы не загрузятся. Сохранить решение на будущее: `/trust`.

### Шаг 4. Проверка

- `/mcp` — видны серверы из `.pi/mcp.json` (chrome-devtools, ssh-connect, sftp-connect — лишние можно удалить из конфига);
- в чате: «покажи список субагентов» — должны быть browser-checker, docs-maintainer, test-runner, test-fixer, server-operator, sftp-operator, server-deployer, html-designer.

### Шаг 5. Онбординг

Попросите агента: **«пройди онбординг»** — по `.ai/playbooks/bootstrap.md` он создаст `.ai/PROJECT.md` (карточка: стек, команды, env). Для пустого проекта сначала спросит про назначение и стек. Дальше работайте через роутер `AGENTS.md`; выполняя задачи, агент будет вести `Задачи.md` и `Описание.md`.

## Сценарий 3 — внедрение в существующий (работающий) проект

Здесь главное — **не затереть то, что уже есть**.

### Шаг 1. Осмотр (не копируем вслепую)

Проверьте в проекте: `AGENTS.md` / `agents.md` / `CLAUDE.md`, папки `docs/`, `.cursor/`, `.github/copilot-instructions.md` и т.п.

- **`AGENTS.md`/`CLAUDE.md` уже есть** → НЕ перезаписывайте: скопируйте только `.ai/` и `.pi/`, а существующие проектные правила перенесите в `.ai/PROJECT.md` (секция «Соглашения проекта»). Позже можно заменить корневой файл роутером по шаблону `.ai/templates/AGENTS-project.md`.
- **Файл называется `agents.md` (нижним регистром)** → переименуйте в `AGENTS.md`: pi автозагружает именно `AGENTS.md`, на Linux-сервере строчный вариант молча игнорируется.

### Шаг 1–2. Осмотр + установка (одним шагом)

Скрипт безопасен для работающего проекта: **не перезаписывает** `AGENTS.md`, `.ai/PROJECT.md`, `Задачи.md`, `Описание.md`, `.env` — при конфликте кладёт комплектную версию рядом (`AGENTS.kit.md`).

Можно через мастер: `node УСТАНОВКА/setup.mjs` → **«3 — Внедрить комплект в существующий проект»**. Или вручную:

```bash
node <путь>/agent-starter-kit/scripts/kit-install.mjs <путь-к-проекту>
```

Флаги `--no-pi`, `--no-ssh`, `--registry-url <url>` — см. `scripts/kit-install.mjs --help` в шапке файла. Если проектный `AGENTS.md` уже был — сравните его с появившимся `AGENTS.kit.md` и объедините.

<details><summary>Вариант вручную (без скрипта)</summary>

```bash
cp -r <путь>/agent-starter-kit/.ai <путь>/agent-starter-kit/.pi <путь>/agent-starter-kit/.agents .
cp <путь>/agent-starter-kit/.env.example .
```

</details>

### Шаг 2. Адаптировать `.pi/`

1. Удалите из `.pi/mcp.json` неиспользуемые серверы и из `.pi/agents/` ненужных агентов (например, нет удалённого сервера — уберите `ssh-connect`, `sftp-connect`, `server-operator`, `sftp-operator`, `server-deployer`).
2. В `.pi/agents/server-deployer.md` замените плейсхолдеры `<PROJECT>`, `<USER>`, `<SSH_PORT>`, `<SERVICE>`, `<SERVER_IP>` на значения проекта (или держите их в `.ai/PROJECT.md`).
3. Если нужен ssh/sftp — `.env.example` → `.env` с реальными кредами и снимите `"enabled": false` у `ssh-connect`/`sftp-connect` в `.pi/mcp.json`; проверьте, что `.env` в `.gitignore`.
4. Подробности формата — `.pi/README.md`.

### Шаг 3. Запуск и доверие

```bash
pi
```

Подтвердите trust, затем `/trust` для запоминания. Проверки — как в сценарии 2, шаг 5.

### Шаг 5. Онбординг

Попросите агента: **«пройди онбординг»**. По `.ai/playbooks/bootstrap.md` он осмотрит код, не читая всё подряд, и создаст `.ai/PROJECT.md` из реальных фактов (что не выяснит — пометит `?`). Если в проекте уже есть документация — он сослется на неё, а не продублирует.

### Шаг 5. Закоммитить

`.ai/`, `.pi/`, `AGENTS.md` — командный артефакт, коммитьте в репозиторий проекта. `.env`, `.idea/`, артефакты тестов (`playwright-report/`, `test-results/`) — в `.gitignore`.

## Как работают `.env.example` и `.env`

`.env.example` — **шаблон-заготовка** файла с секретами: имена переменных есть, значений нет:

```bash
SSH_HOST=          # ← IP сервера
SSH_PORT=22
SSH_USER=          # ← пользователь на сервере
SSH_PASSWORD=      # ← пароль
```

Он нужен **только агентам, работающим с сервером**: `server-operator`, `sftp-operator` и `server-deployer`. Цепочка:

```
субагент → MCP ssh-connect / sftp-connect → scripts/ssh.sh (sftp.sh) → читает .env → подключение к серверу
```

### Когда сервер нужен

1. Скопируйте шаблон в корень проекта: `cp .env.example .env`
2. Впишите реальные значения (IP, порт, пользователь, пароль)
3. Проверьте, что `.env` в `.gitignore` — пароли никогда не должны попадать в git

После этого агенты смогут подключаться: «проверь состояние сервера через server-operator».

### Когда сервера нет

`.env.example` можно не копировать или удалить. Но тогда уберите из `.pi/` лишнее, чтобы агент не пытался подключаться к несуществующему серверу:

- в `.pi/mcp.json` записи `ssh-connect` и `sftp-connect` уже отключены (`"enabled": false`) — можно оставить как есть или удалить;
- из `.pi/agents/` удалите `server-operator.md`, `sftp-operator.md`, `server-deployer.md`.

### Главное правило

`.example`-файл — **публичный** (шаблон без секретов, коммитится в git), `.env` — **приватный** (реальные пароли, в git не попадает). Тот же паттерн используется в `dot-pi-agent/models.example.json` для API-ключей.

## Чек-лист «всё работает»

| Проверка | Как |
|----------|-----|
| pi запускается | `pi` в терминале |
| Модель подключена | `/model` — есть ваш провайдер |
| Пакеты загружены | `/settings` → packages: `pi-subagents`, `pi-animations`, `pi-tps-was-taken` |
| MCP-серверы проекта | `/mcp` — список с источником конфига |
| Субагенты проекта | чат: «покажи список субагентов» |
| Доверие к проекту | `/trust` сохранено (не спрашивает при каждом запуске) |
| Онбординг выполнен | есть `.ai/PROJECT.md` |

## Проблемы

- **Pi не видит агентов из `.pi/agents/`** → не установлен `pi-subagents` (шаг 5 сценария 1) или не подтверждён trust.
- **`/mcp` пустой** → нет `.pi/mcp.json` в проекте или проект без trust (встроенный MCP pi 0.99+ читает его только в доверенных проектах); после правки конфигов — `/reload`.
- **Агент отвечает не на русском** → проверьте `APPEND_SYSTEM.md` в `~/.pi/agent/` (сценарий 1, шаг 4).
- **MCP-инструменты недоступны субагенту** → записи `mcp:<сервер>` в `tools:` frontmatter агента + перезапуск pi после правки конфига MCP.
